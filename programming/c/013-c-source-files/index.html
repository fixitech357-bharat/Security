The Big Difference

Source Files vs Header Files

Both are text files. Both contain C code. But they serve completely different purposes. Here is the side-by-side comparison:

Aspect 📄 Source File (.c) 📘 Header File (.h)
Purpose Contains the actual implementation — the code that does the work. Contains declarations — a description of what exists.
Contents Function definitions, main(), real logic. Function prototypes, macros, struct definitions, constants.
Compiled? Yes — each .c becomes an object file (.o). No — headers are inserted into .c files by the preprocessor.
Included by Compiled directly by the compiler. Included via #include at the top of source files.
Multiple copies? Usually one .c per module. Included in many .c files — must use header guards.

Recap

What You Just Learned

Multi-file C projects are the norm in the real world. Here's the summary:

.c = Implementation
Source files contain the real code. Each one becomes an object file.
.h = Declaration
Header files tell other files what exists. They are not compiled directly.
#include Pastes Files
The preprocessor literally inserts the header's contents into the .c file before compilation.
Always Use Guards
Wrap every .h file in #ifndef / #define / #endif to prevent duplicate inclusion.
