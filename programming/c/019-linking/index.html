📦 main.o — Your Object File
This is the object file produced by compiling main.c. It contains the machine code for your functions, but it has unresolved symbols — calls to functions like printf() that live somewhere else. The linker's job is to find them.
Two Approaches

Static vs Dynamic Linking

There are two fundamentally different ways to link a program. Each has trade-offs for size, speed, and portability.

📦
Static Linking
The library code is copied directly into the final executable at link time. The result is one self-contained file.
  • Larger executable size
  • No dependencies at runtime
  • Faster startup (no loading)
  • Uses .a or .lib files
🔗
Dynamic Linking
The library code stays in a separate shared library. The executable contains only a reference to it, resolved at runtime.
  • Smaller executable size
  • Depends on library being present
  • Slower startup (must load .so)
  • Uses .so or .dll files
💡
Real-world: Linux systems usually use dynamic linking for the standard C library (glibc). That's why you can update glibc and all programs benefit. Static linking is common for tools that need to run standalone (like BusyBox or embedded systems).

Troubleshooting

Common Linker Errors

Linker errors are different from compiler errors. They happen after compilation succeeds. Here are the most common ones:

undefined reference to 'foo'
The linker could not find the definition of foo. You declared it, but never defined it — or forgot to compile the file that defines it.
Compile all .c files, or check the function name for typos.
multiple definition of 'bar'
Two different object files both define bar. This usually happens when a variable or function is defined in a header (which is included by multiple .c files).
Use extern in the header, define only once.
cannot find -lmylib
The linker cannot locate a library you asked it to use. Either the library isn't installed, or it's in a directory the linker doesn't search by default.
Add the path with -L and link with -l.
relocation truncated to fit
The linker found a reference that's too far away for the instruction being used. Rare on modern systems, but common in embedded work with limited memory.
Adjust memory model or use -mcmodel flags.

Recap

What You Just Learned

Linking is the final phase that turns object files into a runnable program. Here's the summary:

Joins Object Files
The linker combines all .o files into one executable.
Resolves Symbols
It matches every undefined symbol with a definition from another file or library.
Static vs Dynamic
Static copies library code into the binary; dynamic uses shared libraries at runtime.
Errors Are Different
Linker errors like undefined reference happen after compilation, not during.
